## 2. 主张：四条环，一个账本

```
        制度 / 手册                         检索 / 图谱
        飞书天玑                            E盘 RAG / Obsidian
            │                                    ▲
            │ 只读                               │ 冻结 / 指针
            ▼                                    │
┌─────────────────── 人 + Agent ───────────────────────────┐
│  现场岗  中控  火脱     WorkBuddy Codex Cursor MiniMax     │
└──────────┬─────────────────────────────┬─────────────────┘
           │ 执行 / 拍照关单              │ 改代码 / 改 SOP
           ▼                             ▼
     ┌──────────┐                 ┌─────────────┐
     │ /ops 账本 │◄── TypeSafe ───│ 代码 Canon   │
     │ 工单闭环  │     仅服务端    │ GitHub      │
     └────▲─────┘                 └─────────────┘
          │ 建单 / 派岗
          │
   ┌──────┴──────┐         ┌─────────────┐
   │ 边缘盒子     │ JPEG    │ 火山 TOS    │
   │ classId+置信度────────►│ 方舟 豆包   │ 异步看图，不阻塞建单
   └─────────────┘         └─────────────┘
```

四条环：

1. **检出环**：盒子 → 视觉 API → 收件箱 → 人确认转入工单  
2. **闭环环**：面板派岗 → 飞书通知 → 现场到场拍照 → 中控关单  
3. **判断环**：代码规则先算；不够再 TypeSafe（条线 / 优先级 / 红线 / 岗位）；豆包只写「内容情况 / 分析」  
4. **知识环**：见 Canon 方案，单向派生，不进这条热路径

## 3. 运行时分层

| 层 | 放什么 | 不放什么 |
|---|---|---|
| 边缘 | 检测模型、`classId`、JPEG、`cameraId` | SOP 全文、关单权 |
| 服务端 | 去重、catalog、SLA 数学、TypeSafe compose、机位台账 | 客户端直调 TypeSafe / 方舟密钥 |
| 面板 `/ops` | 列表、详情、看板、建单、席位 | 第二套工单库 |
| 飞书 | Wiki、群卡片、审批 | 正式关单 |
| 方舟 / 豆包 | 看图说明、对照手册措辞 | 改 `classId`、改优先级、自动转入 |
| 知识层 | RAG / Obsidian / Notion / Desktop SOP | 热路径依赖它们在线 |

密钥：`TYPESAFE_API_KEY`、`VISION_API_KEY`、飞书 / Notion token 只在服务端或本机 `.env`。

## 4. 本机模块（已存在，继续长）

```
client/src/ops/          面板：工单、视觉收件箱、CameraBoard、配置
server/vision/           机位台账、事件去重、/api/vision
server/typesafe/         triage + compose，仅服务端
shared/vision.ts         classId 目录、机种（fisheye/hd/starlight）
shared/cameraPlan.ts     188 路部署，DEPLOYED_CAMERA_TOTAL
shared/buildingFloors.ts A00 楼层
shared/sopPlaybook.ts    手册规则（烟火、登高面等）
shared/triage.ts         分诊结果类型
```

接口：

| 路径 | 作用 |
|---|---|
| `GET /api/vision/cameras` | 台账（含星光） |
| `POST /api/vision/events` | 边缘上报，15 分钟去重 |
| `POST /api/vision/events/:id/ticket` | 绑定单号 |
| `POST /api/ops/triage` | TypeSafe 分诊建议，置信度不够则不自动落地 |

工单目前主要在前端 store + seed。架构上账本最终应落到服务端存储；本方案 **不在对比前改存储**，只把边界画清：关单权威在面板，不在飞书。

## 5. 判断权怎么切（和别的方案最容易分歧的地方）

| 事情 | 谁说了算 | 谁可以建议 |
|---|---|---|
| 这是不是登高面停车 | 边缘 `classId` + 代码 catalog | 豆包描述画面 |
| 条线 / 优先级 / 红线 / 派哪一岗 | 代码 playbook；模糊时 TypeSafe，且过置信度门槛 | 豆包、现场口述 |
| SLA 15 分钟 / 逾期 | 代码算 | 无人可改公式在对话里 |
| 楼层、机位、星光 | `cameraPlan` | Agent 沙箱草稿 |
| 关单 | 中控在面板点，必须有照片 | 对讲、飞书「搞定了」无效 |
| P0 建单 | 立刻建，不等模型 | 豆包后到只补分析 |

原则：**规则、目录、数学在代码；语义判断用 TypeSafe；长文本说明用豆包。** 不要把三件事交给同一个大模型。

| 角色 | 系统动作 |
|---|---|
| 边缘 | 只 POST 事件 |
| 中控 | 收件箱转入工单、验收关单 |

三条路径不变：视觉 P0、现场报单、超时升级。P0 到场 15 分钟。红挡禁止口头销单。

## 8. 知识与 Agent（接到 Canon，不在这里再发明一层）

运行时 **不查询** Notion / Obsidian / 桌面文件夹。热路径只碰：

- 代码里的 catalog / playbook / 机位
- 可选：服务端把飞书 SOP 做成检索，给豆包或 TypeSafe 当上下文

Agent 改系统的入口：

1. 读 `CANON.md`
2. 在自己沙箱打草稿
3. 升格进代码仓或桌面 SOP
4. 需要日切时打 `freezes/日期`

六个 Agent 不共享一个 IDE 工作区，只共享 Canon 指针。

## 12. 给对比会用的维度

1. **账本在哪**：面板、飞书、还是多维表格？本方案：`/ops`。  
2. **模型怎么切**：一个大模型包办，还是代码 / TypeSafe / 豆包分权？  
3. **机位事实在哪改**：代码 + A00，还是知识库表？  
4. **P0 是否等模型**：本方案不等。  
5. **本机 UI 是否保留**：本方案保留三栏六模式。  
6. **和 Canon 是否同一套边界**：本方案与 `cursor-canon-v1` 共用可写源表。  
7. **上云是否强迫迁数据**：本方案可上火山，不迁知识库。
